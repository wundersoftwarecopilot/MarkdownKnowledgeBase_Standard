# ADR-002: Render daily reports as PDF with headless Chromium

## Context
Customers get their daily delivery report as a document that marta compiles by hand from the day view; TASK-003 automates it.
The customers asked for a document they can file, print and forward; none has asked for machine-readable data.
The web UI already renders HTML with Jinja2 templates.
Reports must reach customers by 06:00 ([project/CONSTRAINTS.md](../project/CONSTRAINTS.md), section Customer and contract).
The weighbridge PC is a Linux mini-PC with 8 GB of memory.

## Problem
In which format, and with which tool, are the daily per-customer reports rendered?

## Decision
Render each report from a Jinja2 HTML template and print it to PDF with headless Chromium on the weighbridge PC.
The report job writes one PDF per customer and report day and e-mails it as an attachment before 06:00.
The templates live in `src/tarelog/reports/templates/`.

## Alternatives considered
- ReportLab: the layout is Python code, so every layout change is a code change, and multi-page tables need manual page breaks.
- HTML e-mail: looks different in every mail client and cannot be filed as one document.

## Consequences
- Headless Chromium (about 400 MB) becomes a runtime dependency of the weighbridge PC and is updated with the operating system.
- Layout changes are template edits that anyone who knows HTML and CSS can make.
- Rendering takes a few seconds per customer, so the report job starts at 05:00 to stay within the 06:00 deadline.
- Customers who want to import the data into their own systems get nothing machine-readable; revisit this if one asks.
